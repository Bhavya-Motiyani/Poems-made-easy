# Poems: Made Easy

An NLP project that takes a poem as input and provides its **sentiment** and a **simple explanation of its meaning**, using two separately fine-tuned models.

> **Note on purpose:** This project is primarily a demonstration of fine-tuning, parameter-efficient training (LoRA/QLoRA), and evaluation workflows for two different NLP tasks — not a production-ready poetry interpretation tool.

---

## Overview

Poetry can be hard to interpret because meaning is expressed through emotion, metaphor, and indirect language. The app passes a poem through two independent fine-tuned models and displays both results via a simple Flask interface:

1. A fine-tuned **DistilBERT** model for sentiment classification.
2. A fine-tuned **Gemma-2B** model for generating a plain-language explanation.

## Models Used

### Sentiment Classification
**Base:** [`distilbert-base-uncased-finetuned-sst-2-english`](https://huggingface.co/distilbert/distilbert-base-uncased-finetuned-sst-2-english), fine-tuned into a custom 4-class task: **Negative, Positive, No Impact, Mixed**.

### Poem Explanation
**Base:** [`google/gemma-2b`](https://huggingface.co/google/gemma-2b), fine-tuned via **QLoRA** (quantized + LoRA) to generate simple explanations of a poem's meaning. Final LoRA projections: `q_proj`, `k_proj`, `v_proj`, `o_proj`.

Different projection counts (2, 4, 7, plus base) were tested to see whether training more projections meaningfully improved explanation quality.

---

## Evaluation

### Sentiment Model
Evaluated on a 104-sample held-out test set:

| Class | Precision | Recall | F1-score | Support |
|-------|-----------|--------|----------|---------|
| Negative  | 0.85 | 0.89 | 0.87 | 19 |
| Positive  | 0.83 | 0.62 | 0.71 | 16 |
| No Impact | 0.89 | 0.91 | 0.90 | 69 |
| Mixed     | 0.00 | 0.00 | 0.00 | 0  |
| **Accuracy** | | | **0.87** | 104 |

The "Mixed" class had no test samples, so its 0.00 score is untested rather than a failure. "Positive" recall (0.62) was the clearest weak point, likely due to confusion with the dominant "No Impact" class.

### Explanation Model (BERTScore)

| Model | BERTScore |
|---|---|
| Base Gemma-2B | 0.93 |
| 2-projection fine-tuned | Not evaluated (poor qualitative output) |
| 4-projection fine-tuned | 0.88 |
| 7-projection fine-tuned | 0.89 |

The base model scored highest on BERTScore but produced repetitive text and tended to summarize rather than explain — so it wasn't selected despite the metric. 7-projection barely beat 4-projection but needed more stored LoRA weights, so **the 4-projection model was chosen** as the best quality/size trade-off.

A Gemini API experiment was also tried for explanations, but API rate limits prevented generating enough outputs to compute a comparable BERTScore.

---

## Final Models

- **Sentiment:** Fine-tuned DistilBERT, 0.87 accuracy on the held-out set.
- **Explanation:** Gemma-2B + 4-projection QLoRA adapter (`q_proj`, `k_proj`, `v_proj`, `o_proj`), quantized for efficient inference.

---

## Web Application & Inference

Built with Flask, HTML, CSS, and JavaScript (Gradio was explored but not used in the final version). The user enters a poem and hits **Predict**:

- **Sentiment:** tokenized (DistilBERT tokenizer, max 512 tokens) → classified.
- **Explanation:** poem inserted into an instruction prompt → generated by the fine-tuned Gemma model (max 300 new tokens, temperature 0.7, top-p 0.9, repetition penalty 1.1).

**Hardware:** Gemma runs in 4-bit mode on a CUDA GPU when available; otherwise it falls back to slower, more memory-heavy CPU inference.

## Skills Strengthened

- **Fine-tuning:** manual fine-tuning of pre-trained Hugging Face models for both classification and generation tasks.
- **Parameter-efficient tuning:** LoRA/QLoRA, experimenting with target projections, model quantization under hardware limits.
- **NLP evaluation:** BERTScore alongside qualitative review, and why quantitative scores alone can mislead.
- **Development:** Google Colab for training, Flask for deployment, connecting NLP models to a custom frontend.

---

## Challenges Faced

- **Hardware limits:** Fine-tuning Gemma-2B required quantization + LoRA (QLoRA) to be feasible at all.
- **Time-consuming experiments:** Testing multiple projection counts meant training and evaluating several separate configurations.
- **No ready-made dataset:** No suitable poem-explanation dataset existed, so training data was self-generated using Ollama.
- **Gemini API limits:** Rate limits blocked generating enough Gemini outputs to compute a fair BERTScore comparison.

## Installation

```bash
git clone <your-repository-url>
cd <your-repository-folder>

python -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate

pip install -r requirements.txt
pip install -r requirements-gpu.txt   # optional, for NVIDIA CUDA
```

**Hugging Face auth** (required for `google/gemma-2b` access):

```bash
huggingface-cli login
# or: export HF_TOKEN="YOUR_HUGGING_FACE_TOKEN"
```

**Run:**

```bash
python app.py
```

Then open `http://127.0.0.1:5000`.

---

## Limitations

- Explanation quality depends on the training data's diversity.
- BERTScore doesn't always track true explanation quality (see base Gemma model).
- Gemini comparison is incomplete due to API limits.
- Gemma-2B inference is resource-intensive without a CUDA GPU.
- This is a fine-tuning/evaluation demo, not a production system.
